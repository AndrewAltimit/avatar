Tools for the files a VRChat avatar is made of.

avatar reads, diagnoses, fixes, lints, generates, and previews the binary FBX and Unity YAML an SDK3 avatar is built from — then drives the uploaded avatar over OSC. No Unity in the loop until you build & upload; every command runs offline and takes --json.

The pipeline

Every tool sits at one point on the path from a raw export to a live avatar. Click a step to jump to its reference.

.fbx Inspect avatar fbx inspect Hierarchy, units, axes, blendshapes, unapplied transforms. → .fbx Armature check / fix avatar armature fix Humanoid mapping, canonical renames, Blender repair script. → Unity project Lint avatar lint SDK3 compliance across descriptor, params, menus, animators, clips. → .fbx / project Stats avatar stats VRChat performance rank, PC and Android, offline. → Unity YAML Generate / edit avatar toggle · anim-gen · asset set Clips, FX controllers, params, menus; surgical in-place edits; SDK2 → SDK3. → VRCSDK Build & upload (you, in Unity) Not ours: interactive login, effectively Windows-only. → live OSC avatar osc Send, capture, replay parameters; the analog-gesture daemon.

Preview sits alongside the whole chain: avatar render / avatar view draw the avatar, a world, or the avatar at the world's spawn without Unity. The full picture is on How it stacks.

The two-layer model

Read this first. There are two file layers we own in Rust, and one step we don't.

1 3D asset · .fbx
Armature/skeleton, bone names, bind poses, skinning weights, blendshapes. Fully ours — native binary read and write via fbxcel.
2 Unity / VRChat · YAML
.anim, .controller, .asset, .prefab, scenes, .meta: descriptor, animator layers, menus/params. Read, lint, generate, and edit in place.
3 Upload · not ours
The VRCSDK control panel → VRChat servers. Interactive account login, effectively Windows-only. We hand off assets; you upload.

Where the build is

Status: early / alpha
The crates build green and are covered by tests (synthetic fixtures in CI, sample-gated real assets on the self-hosted runner), generated assets pass a headless Unity import-acceptance gate, and a real SDK2 avatar has been migrated, built, and uploaded to VRChat with these tools. Still: expect rough edges, verify in Unity before you rely on output, and treat APIs, CLI flags, and report formats as subject to change.

project · VRChat SDK3 / Avatars 3.0 · Rust monorepo

avatar tools for the files a VRChat avatar is made of

A Rust monorepo that operates on the files a VRChat SDK3 avatar is built from — binary FBX and Unity YAML — to diagnose, fix, lint, generate, and drive them, plus an OSC runtime layer. It does not replace Unity or the VRChat SDK upload step: you still build & upload in Unity. These tools handle everything up to that point, and the live OSC layer after it.

Status: early / alpha (WIP)
The crates build green and are covered by tests (synthetic fixtures in CI, sample-gated real assets on the self-hosted runner), generated assets pass a headless Unity import-acceptance gate, and a real SDK2 avatar has been migrated, built, and uploaded to VRChat with these tools. Still: expect rough edges, verify in Unity before you rely on output, and treat APIs, CLI flags, and report formats as subject to change.
Try it without installing anything: the FBX analyzer runs the actual Rust diagnose graph as WebAssembly in your browser — drop an avatar .fbx, get the humanoid rig check and VRChat performance rank. The file never leaves your machine.

The two-layer model

Read this first. There are two layers we own in Rust, and one we don't.

3D asset layer · .fbx
Armature/skeleton, bone names, bind poses, skinning weights, blendshapes. Fully ours — native binary read and write via fbxcel.
Unity / VRChat layer · UnityYAML
.anim, .controller, .asset, .prefab, scenes, .meta: humanoid mapping, Avatar Descriptor, animator layers, expression menus/params. Read/lint & generate.
Upload / build · not ours
The VRCSDK control panel → VRChat servers. Interactive account login, effectively Windows-only. We hand off generated assets; you upload.

What you can do today

Fix the armature
Canonicalize a raw Mixamo rig so Unity auto-configures it as Humanoid. Topology / scale / orientation issues are flagged. avatar armature fix.
Lint a project
SDK3 compliance over an entire Unity project: params, menus, descriptor refs, visemes, animator controllers. avatar lint — exits non-zero for CI.
Rank performance offline
VRChat's Excellent→Very Poor rank computed without Unity, against PC + Android limits. avatar stats.
Generate assets
Emit .anim clips, blend trees, full FX controllers, expression params/menus — or a complete toggle bundle in one command. Deterministic, diffable fileIDs. avatar anim-gen / avatar toggle.
Migrate SDK2 → SDK3
Retype the descriptor in place, convert DynamicBone → PhysBone by the SDK's own rules, build FX from gesture overrides, and get a VCC-openable project. avatar migrate sdk3.
Tune PhysBones
Inspect and retune a prefab's PhysBones in place — values, per-chain curves, split / stretch / re-angle chains — with render previews. avatar physbone.
Preview without Unity
Headless GPU renders of the avatar, a world scene, or the avatar at the world's spawn — plus an interactive orbit/zoom/walk viewer. avatar render / avatar view.
Drive avatars over OSC
Speak VRChat's OSC parameter protocol, capture + replay parameter streams, and run the analog-gesture daemon — "Vive advanced controls on any hardware". avatar osc.
Hand it to an agent
--json + JSON Schemas across the read surface, and an MCP server exposing the diagnose/generate tools to any agent host. avatar mcp serve.
Browse the crates
Twenty-two crates from FBX I/O through migration and the runtime rig layer to the OSC daemon — purpose, key API, and status for each.

Where the build is

Built and green through M5: diagnose/lint, native FBX read + write with armature repair, asset generation (M4), the OSC runtime + analog-gesture daemon (M5) — plus the layers that landed alongside: surgical Unity-YAML editing, SDK2 → SDK3 migration with PhysBone tuning, the runtime rig layer, the wgpu preview/viewer, and the agent surface (--json everywhere, avatar mcp serve). In flight: the daemon's on-device OpenXR input backend and OSCQuery browse/resolve discovery. The full roadmap of record lives in PLAN.md; this site mirrors the committed docs under docs/.
